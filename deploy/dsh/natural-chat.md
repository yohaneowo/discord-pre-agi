# 自然接话阶段

2026-10-28 更新：已补上真正 dsh 主程式配合假 Discord／模型的隔离验收，包含无 @ 接话与续聊；指定频道可由普通群友聊天，群聊只开放记忆工具。最新版本 `0.6.0-social.2`，长期记忆、群聊／私讯隔离及统一用量见 [整合说明](social-runtime.md)。以下保留前一阶段的开发与人工测试纪录，人工体验评价仍待使用者继续观察。

2026-10-27：使用者指出「必须 @ 才说话不像人」。原先的提及限制只作为桥接连线验收，现已改为直接呼叫、短时间续聊及有限度主动插话。用户及频道白名单沿用拥有者测试范围，未扩大群友的工具权限。

## 现在如何接话

- @、叫 bot 名字／「鲸鱼娘／大肥鱼／小鲸鱼」（含繁体）或直接回复 bot，都可以进入原 dsh 会话，不需要每次 @。
- bot 已回复某人后，同一人短时间内继续说话会接续对话；此时不套用主动插话的冷却。单纯收尾、回复其他人或明确提及其他人时，不自动视为续聊。
- 其他普通群讯息也会进入有限的频道背景，再以 dsh 的默认模型判断是否值得接一句；不适合、格式错误、取消或失败便保持安静。
- 只保留最近 30 则背景，每则最多 1000 字元，判断只看最近 6 则；名字和群讯息作为资料封装，不具备改权限或系统设定的效力。
- 主动判断不带工具，关闭 reasoning，最多输出 96 tokens；决定接话后才沿用原桥接及人设回复。

第一次实测发现正常续聊也被插话冷却挡住，已修正为短暂对话窗口：默认 2 分钟内同一人的接续不算主动插话，计时以 bot 最近实际送出回覆为准。

## 默认节奏

| 设定         | 默认行为                                                   |
| ------------ | ---------------------------------------------------------- |
| 安静时段     | Asia/Taipei 00:00～08:00，不主动插话；直接呼叫与续聊仍可用 |
| 主动冷却     | 全域 10 分钟，只约束主动插话                               |
| 判断间隔     | 同频道至少 60 秒，短暂等待 1.5 秒让连续消息合并背景        |
| 每日主动上限 | 10 次尝试，呼叫前保守占额                                  |
| 每日判断上限 | 60 次，失败也计入已保留次数                                |
| 连续发言     | 最近 8 则若已有至少 2 则自己的发言，不主动抢话             |

拥有者可直接发送文字 `/安静 10` 或 `/安靜 10`，暂时关闭主动插话 10 分钟；允许 1～1440 分钟，不呼叫模型。它是文字命令，没有注册新的 slash picker 项目。

可在 VM 保护的 `.env` 调整 `BOT_NAMES`、`BOT_TIMEZONE`、`QUIET_START_HOUR`、`QUIET_END_HOUR`、`PROACTIVE_COOLDOWN_MINUTES`、`DECISION_INTERVAL_SECONDS`、`DAILY_PROACTIVE_LIMIT`、`DAILY_JUDGMENT_LIMIT`，重启服务生效。每日次数限制不等于美元预算，不能据此宣称每日费用有硬上限。

## 持久化与异常

`participation-state.json` 保存日期、次数、冷却及安静截止时间。先占额并成功落盘才判断，避免重启或跨频道并发绕过限制；损坏时停用主动判断，直接呼叫仍可用。最近频道背景与短暂续聊窗口在记忆体，原 dsh 会话历史仍由原持久化负责，跨会话长期记忆尚未实现。

`participation-judgments.jsonl` 在 VM 的私人 profile 中保存实际判断请求、可见输出、完成状态与 token 用量，0600，不写服务终端或程式仓库。判断调用属于额外模型用量，不进入原型的 SQLite ledger。

判断期间若有新的消息，旧判断会失效；直接呼叫优先，正在进行的判断可取消，避免迟来的主动回复打断新问题。管理命令与开启新会话也会使旧的回复票据失效。

VM 本次使用新的版本目录 `/opt/dsh/vendor/discord-0.6.0-natural.3`。不能只改同一路径的 `file:` 依赖：本次 pnpm 即使重新 add／force 仍使用旧快取，直到改用版本目录并通过 `verify_discord.mjs` 才确认新代码已安装。下次更新也应使用新版本目录及实装验证，勿凭 CLI 显示成功判断。
