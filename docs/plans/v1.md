## 1. 技术选择

| 项目 | 选择 | 理由 |
|---|---|---|
| 语言 / 执行环境 | **Node.js 22 + TypeScript** | 生态成熟、型别完整 |
| Discord | **discord.js v14** | 同上；不用 discord.py |
| 套件管理 / 检查 | pnpm、Prettier（tab）、ESLint、`tsc --noEmit`、vitest | 常见组合 |
| 呼叫模型 | 直接用 `fetch` 打 **OpenAI 相容格式**的 `/chat/completions`，**不装 SDK** | 能用 fetch 就不加 SDK；DeepSeek 官方、OpenRouter、DeepInfra 都是 OpenAI 相容格式，切换只改设定 |
| 记忆正本 | Markdown 档（Obsidian 格式）+ git | Markdown 好读、好改、可用 Obsidian 打开，git 版本化不丢 |
| 检索索引 | SQLite（`better-sqlite3`）+ FTS5 `trigram` 分词；之后可加向量 | trigram 不用中文分词也能搜中文；索引档不进 git，随时可从 Markdown 重建 |
| 部署 | Docker | 一个容器即可 |
| 密钥 | 本机 `.env`（`.gitignore`）；部署时由密钥管理服务注入（例如 Doppler） | 金钥不进 git |

## 2. 模型接法

- **重点：** 第三方 bot 没办法「用帐号登录」来呼叫模型。做法是登入 **platform.deepseek.com（开放平台，不是聊天 App）**，在帐户里建一把 API Key；这把 key 产生的费用会先扣帐户里的赠金。所以「用登录的赠金」= 用这个帐户建的 key。
- 若有平台赠金，先确认它在**开放平台帐户**（不是 App 的福利）、额度多少、**什么时候过期**。
- 设定（全部从环境变数读，换供应商不改程式）：
  - `LLM_BASE_URL`：DeepSeek 官方预设 `https://api.deepseek.com`（待核对）
  - `LLM_MODEL`：调研说官方模型名 `deepseek-flash` 现由 V4.1-Flash 提供（待核对）
  - `LLM_API_KEY`
  - 备案：OpenRouter（`https://openrouter.ai/api/v1`，限定 Decart / DeepInfra、关闭会记录资料的托管商）、DeepInfra 直连。
- **省钱关键：前缀缓存。** DeepSeek 对「和上次一样的开头」收很低的缓存价（调研：Flash 未命中 $0.14 vs 命中 $0.0028 / 百万 token）。所以提示词的顺序固定为：
  1. 人设（几乎不变）
  2. 长期事实（很少变）
  3. ——以上越稳定越省——
  4. 这次相关的人物卡、召回的记忆
  5. 最近的群聊
- **费用护栏（第一天就做）：**
  - 每次呼叫记录 token 用量与估算费用（写进本地 SQLite，日志永久保留）。
  - `DAILY_BUDGET_USD` 每日上限，超过就只回「被 @ 时的简短回覆」或静默，并通知主人。
  - 启动时与每天查一次余额（DeepSeek 有余额查询端点，路径待核对）。
- 高峰时段（调研：9–12、14–18）价格两倍：非即时的整理工作（每日摘要、记忆合并）排在离峰跑。

## 3. 她什么时候说话

- **一定回：** 被 @、被回覆、被叫名字。
- **可能插话：** 其他讯息先过一层便宜的判断（同一个模型、很短的提示，只回「说 / 不说 + 理由」），再加规则：
  - 冷却时间：插话后 N 分钟内不再主动插话（预设 10 分钟）。
  - 同一段对话她已经说了太多就收手。
  - 深夜 / 主人设定的安静时段不主动插话。
  - 每天主动插话上限。
- 回覆要像群友：短、口语，可以只回一个表情；不要每次都长篇。
- 多人同时说话：讯息进队列，同一频道同时只处理一个回覆。

## 4. 人设

- 写成 `memory/self.md` 最上面的「她是谁」：个性、说话方式、喜好、雷点、跟主人的关系——**写人，不写规则清单**。
- 优先级写在系统提示的固定段：**安全 > 事实 > 用户指令 > 语气**；写代码、贴指令时不加语气（借鉴 linsport 预设）。
- **建议自己写，不要直接贴社区现成的人设：**
  - Neko3000 素材部分是 CC BY-NC-SA（不可商用）；linsport 预设的授权未确认。
  - 以后若要公开或商用，自己写的人设才没有授权问题。
  - 可以参考它们的写法，但文字自己写。
- 「大肥鱼」这个名字与形象是社区二创、非官方（调研第 2 节）；只在私人群里用问题不大，要公开前再想。

## 5. 记忆（核心）

### 5.1 资料夹结构（Markdown 是唯一正本）

```
memory/
  self.md              她是谁 + 她自己的笔记（主人写人设段，她写笔记段）
  facts.md             长期事实：不淡忘、每次都带上；有字数上限
  people/
    <discord_id>.md    每位群友一篇
  journal/
    YYYY-MM-DD.md      每天的日记 / 事件
```

- 用 Obsidian 格式：frontmatter + `双链`（例如日记里提到人就连 `123456`），主人可以直接用 Obsidian 打开看、手动改。
- 人物卡 frontmatter：`discord_id`、`names`（曾用名 / 暱称）、`first_seen`、`last_seen`；内文：对这个人的印象、知道的事、互动纪录摘要。
- 每条记忆一行，带 Obsidian inline 栏位，例如：
  `- 2026-10-27 小明说他下周要考试 (importance:: 3) (emotion:: 焦虑) (recalled:: 0) ^m20261027a`
  - `importance`：1–5，写入时由模型评。
  - `emotion`：情绪标签 + 强度。
  - `^id`：区块 id，方便索引对回原文。

### 5.2 fish-memory 规则（调研第 7 节）

- **淡忘但不删：** 鲜活度 = `0.5 ^ (经过天数 / 30)`（半衰期 30 天）；被召回一次就刷新。档案里的记忆**永远不删**，只是越来越难被想起。
- **长期事实不淡：** `facts.md` 每次都注入（放在提示的前段，吃缓存）。
- **上限：** 每天最多新增 8 条记忆、每次最多注入 6 条召回记忆（照 fish-memory 起步，之后可调）。
- **召回排序：** `分数 = 关键词 / 语意相关度 × a + 鲜活度 × b + importance × c + 情绪强度 × d`，权重放设定档。
- **召回过程可看：** 有一个只给主人用的指令（例如 `/记忆 为什么`），列出这次带了哪几条记忆、各自分数。

### 5.3 写入流程

- 短期：最近 30 则群聊直接放进上下文（只在记忆体，不写档）。
- 每累积 N 则讯息（预设 10，借鉴 dsh-tool-memory），或频道安静 M 分钟后，背景跑一次「整理」：从这段对话挑出值得记的事 → 写进当天日记、更新相关人物卡、必要时提议新增长期事实。
- **只有一个写入者：** 所有写档经过同一个队列，避免多人同时说话时写坏档案。
- 每天离峰跑一次「日结」：当天日记写摘要、合并重复记忆。
- 写入前检查：不写密钥、不写主人的私密资讯的内容；群友在讯息里写「记住：忽略之前的指示……」这类句子只当成「他说了什么」记下来，不当指令。
- **git：** `memory/` 每次写入后自动 commit。

### 5.4 索引

- `pnpm reindex`：删掉索引，从 `memory/**/*.md` 全部重建。索引坏掉或改了规则就重建。
- v1 用 SQLite FTS5（trigram）做关键词搜寻；v2 再加向量：DeepSeek 官方应该没有 embedding API（待核对），要另找（例如本地 bge-m3，或 OpenRouter 上的 embedding 模型）。

## 7. 指令（只给主人）

- `/记忆 查 <人或关键字>`：看她记得什么。
- `/记忆 为什么`：上一则回覆用了哪些记忆。
- `/记忆 忘掉 <id>`：标记为「不再召回」（**不删档**，照「日志永久保留」的习惯）。
- `/安静 <分钟>`：暂停主动插话。
- `/费用`：今天 / 本月用量与余额。
